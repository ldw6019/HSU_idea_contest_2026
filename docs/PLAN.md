## 구현 계획

### 기술 선택
| 항목 | 선택 | 이유 |
|---|---|---|
| 형태 | 크롬 확장 (Manifest V3) | 현재 표준 |
| 언어 | 순수 JavaScript, 빌드 도구 없음 | 디버깅이 쉬움 |
| 화면 | Shadow DOM + CSS | e클래스 CSS와 간섭 없음 |
| 캘린더 | FullCalendar (lib/에 포함) | 학교 사이트들도 쓰는 검증된 라이브러리 |
| 저장 | chrome.storage.local | 캐시·설정 |
| AI 서버 | Cloudflare Workers + KV | 무료 범위, 키 숨김, 요약 캐시 |

### 전체 구조
```
[e클래스 페이지] content script
  ├ e클래스 데이터 직접 읽기 (같은 사이트)
  ├ 패널·배지 그리기 (Shadow DOM)
  └ 다른 사이트 데이터는 service worker에 요청

[service worker] background.js
  ├ 비교과: 캘린더 JSON, 목록, 마이페이지
  ├ 종합정보: 시간표 JSON (EUC-KR 변환)
  ├ 캐시 관리
  └ AI 서버 호출

[Cloudflare Worker]
  └ 안내문 → LLM 요약 → KV 저장 → 같은 프로그램은 저장본 반환
```
content script는 다른 사이트에 직접 요청할 수 없어서 service worker가 대신 받아온다.

### 공통 데이터 형식 (core/model.js)
```js
{
  source: "eclass" | "hsportal" | "info",
  type: "class" | "assignment" | "video" | "program",
  title, course, start, due,
  status: "todo" | "done" | "late" | "missed",
  url
}
```
어댑터가 사이트별 데이터를 이 형식으로 바꾸고, 화면은 이 목록만 정렬해서 그린다.
사이트 구조가 바뀌면 해당 어댑터 하나만 고치면 된다.

### 새로고침 규칙
| 데이터 | 주기 |
|---|---|
| e클래스 과제·영상 | 메인 접속 시, 30분 경과 시 |
| 시간표 | 하루 1번 |
| 비교과 일정·목록 | 3시간마다 |
| AI 요약 | 프로그램당 1번 |
동시 요청 수를 제한해 학교 서버 부담을 줄인다.

### 위험과 대비
| 위험 | 대비 |
|---|---|
| 다른 사이트 요청이 로그인 상태로 안 됨 | M1에서 가장 먼저 검증. 안 되면 사용자가 그 사이트를 열 때 데이터를 저장하는 방식으로 전환 |
| 학교 사이트 구조 변경 | 어댑터 분리, 실패 시 해당 칸만 "불러오기 실패" |
| 개발 시간 부족 | 필수(1~18번) 유지, 5단계 생략 |
| 개인 데이터 노출 | 테스트 HTML은 개인정보 제거 후 저장, 저장소 비공개 |
| LLM 비용·키 유출 | 키는 Worker에만, 요약 캐시, 하루 호출 수 제한 |
