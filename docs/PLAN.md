## 구현

### 기술 선택
| 항목 | 선택 | 이유 |
|---|---|---|
| 형태 | 크롬 확장 (Manifest V3) | 현재 표준 |
| 언어 | 순수 JavaScript, 빌드 도구·외부 라이브러리 없음 | 디버깅이 쉬움, 캘린더도 직접 그림 |
| 화면 | Shadow DOM + CSS, 글자는 textContent로만 | e클래스 CSS와 간섭 없음, 끼워 넣은 HTML 실행 막음 |
| 저장 | chrome.storage.sync(내 설정) + local(학교 데이터 캐시) | 내 설정은 크롬끼리 동기화 |
| AI 서버 | Cloudflare Workers + D1 | 무료 범위, 키 숨김, 횟수·비용 한도 |
| AI 모델 | Claude Haiku 5.5 (설정 한 줄로 Gemini 등 교체) | 싸고 빠름 (비교 시험 worker/eval) |

### 전체 구조
```
[e클래스 페이지] content script (content/)
  ├ 패널 그리기 (이번 주·캘린더·비교과·AI) / 강의실 표시 (course.js)
  └ 학교 데이터·AI는 service worker에 요청

[service worker] background.js
  ├ 학교 사이트 읽기 (학교 주소만, 동시 요청 제한) → adapters/
  ├ 캐시 (core/cache.js)
  └ AI 서버 호출 (직접 쓴 질문만)

[AI 서버] worker/ (Cloudflare Worker)
  └ 질문 + 최소 정보 → 모델 → 답 거르기(범위 밖·링크·지어낸 날짜·없는 번호) → 확장
```
content script는 다른 사이트에 직접 요청할 수 없어서 service worker가 대신 받아온다.
사이트 구조가 바뀌면 해당 어댑터 하나만 고치면 된다.

## 결정 사항 (2026-10-07, 기록)
> 처음 정한 내용이에요. 바뀐 부분은 → 뒤에 적었어요.

### LLM
- 시연 모델: **Claude Haiku 4.5** (학교 AI 플랫폼 AI헬피챗에도 있는 모델). M4에서 실제 안내문으로 Gemini Flash Lite와 품질 비교 가능.
  → **Claude Haiku 5.5**로 연결(10/19). Gemini 3.8 Flash 등과 비교 시험(worker/eval)
- 연결: 확장 → 우리 Cloudflare Worker → 모델. API 키는 Worker에만, 모델 교체는 설정으로. → 그대로 (`AI_PRESET` 한 줄)
- 사용처: 비교과 안내문 요약(프로그램당 1회, 공유), 추천 이유(기본 템플릿), 자연어 질문(선택 기능).
  → AI 탭의 직접 쓴 질문 하나로 모음. 안내문은 규칙 분류
- 비용 추정(Haiku): 요약 1건 약 6원 → 한 학기 약 300건, **학교 전체 약 2천 원**. 자연어 질문은 사용량 비례라 선택 기능.
  → 실측: 질문 1회 약 0.5원 (Haiku 5.5, 143회 $0.05)
- 학교 AI 플랫폼(엘리스 AI헬피챗) 기관 API 연동은 미확인 → 보고서는 어느 경우든 성립하게 작성. 학생 로그인으로 헬피챗을 자동 조작하지 않음. → 그대로

### 비교과 변동 대응
- 프로그램 번호 + 안내문 해시로 신규/변경/유지/마감/삭제 판별, 바뀐 것만 다시 요약.
- 매일 **00:30 KST**(= 15:30 UTC) Worker Cron으로 확인. 실패 시 1~2시간 뒤 재시도.
- 요약 전에는 "요약 준비 중" + 마감·정원 등 기본 정보는 실시간 표시.
- 전제: 비교과 목록·상세가 로그인 없이 보이는지 M2에서 확인. 안 되면 "처음 볼 때 요약"(여러 사용자에게서 같은 해시 확인 후 공유) 병행.

→ **서버가 매일 학교 사이트를 읽는 Cron은 하지 않음** (10/14: 비교과 사이트 robots.txt가 `Disallow: /`). 학생 확장이 이미 받은 공개 상세 화면을 브라우저에서 12시간 보관하고 규칙으로 분류. 서버의 안내문 해시 공유 분류(/v1/classify)는 준비만 됨
